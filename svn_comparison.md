# Git vs SVN: сравнительный анализ

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на определённый коммит (файл размером ~41 байт).
Создание ветки не копирует файлы, а лишь создаёт ссылку. Поэтому операции с ветками
мгновенные: `git branch`, `git checkout`, `git merge` работают за миллисекунды.

В SVN ветка — это физическая копия директории в репозитории (через `svn copy`).
При создании ветки сервер вынужден копировать структуру папок, что занимает время
и место. Переключение между ветками требует обращения к серверу и часто долгое.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система: коммит отправляется на центральный
сервер и фиксируется там. Без соединения с сервером коммит невозможен.
Можно только сохранить локальные изменения в рабочей копии, но не зафиксировать их.

В Git коммит делается локально (в свою полную копию репозитория), и только `git push`
требует интернета. Можно сделать десятки коммитов в самолёте и запушить их позже.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты.** Большие банки, госструктуры, где десятилетиями используется SVN
  и миграция на Git слишком дорогая и рискованная.
- **Бинарные файлы и артефакты.** SVN лучше работает с большими бинарниками
  (хотя есть Git LFS).
- **Жёсткий контроль доступа к отдельным папкам.** В SVN можно гибко настроить права
  на отдельные директории; в Git права даются на весь репозиторий.
- **Простые линейные проекты без активного ветвления.** Если команда не использует
  ветки и PR, SVN может быть проще.
